# Framo

PPT로 만들던 발표 자료를 HTML로 쉽게 만드는 도구입니다. 어느 한 직무나 회사 보고만을 위한 것이 아니라, 보고, 제안, 공유, 교육, 소개처럼 어떤 발표든 만듭니다.

- **결정을 받는 발표:** 사업 제안, 개선 제안, 여러 안을 견준 검토 보고, 연간 계획
- **진행과 결과를 알리는 발표:** 주간·월간 업무 보고, 실적 보고, 결과 보고, 문제·장애 보고
- **알리고 나누는 발표:** 프로젝트 착수, 조사·분석 보고, 지식 공유와 교육, 팀과 업무 소개

듣는 사람도 정해 두지 않습니다. 본부장·임원, 팀장, 팀 동료, 다른 부서, 여러 분이 함께 듣는 자리 가운데 고르면 그 자리에 맞게 장을 고릅니다.

어떤 발표인지(종류, 듣는 사람, 시간, 방식)를 고르면 장 구성과 레이아웃이 잡히고, 사람은 내용만 채우면 됩니다. 모양을 바꾸고 싶으면 컴포넌트를 끌어다 놓습니다. 놓는 순간 줄과 칸에 맞춰 붙고 간격과 글자 크기는 알아서 맞춰지니, 모양 잡기가 어려운 사람도 반듯하게 나옵니다. 이 PC 안에서만 실행되고, 내용은 어디로도 보내지 않습니다.

소개와 다운로드: **https://wlsdks.github.io/gyeol/**

이름 Framo는 frame(화면의 틀, 영화의 한 컷)에서 왔습니다. 장마다 내용이 한 틀 안에 제자리를 잡고, 한 장이 영화의 한 컷처럼 움직인다는 뜻입니다. 예전 이름은 ‘결’이었고, 저장소와 파일 이름(`gyeol`)은 그대로 씁니다.

## 설치와 실행

[Releases](https://github.com/wlsdks/gyeol/releases/latest)에서 윈도우용(`gyeol-windows.zip`)이나 맥용(`gyeol-mac.zip`)을 받습니다. 둘 다 Node.js가 들어 있어서 크롬이나 엣지 말고는 따로 설치할 것이 없고, 설치 권한도 필요 없습니다. 받은 뒤에는 인터넷 연결도 필요 없습니다(새 버전 알림만 인터넷이 될 때 GitHub에 묻습니다). 맥용에는 애플 실리콘과 인텔 맥의 Node.js가 모두 들어 있습니다.

1. 받은 zip을 **압축 풀기** 합니다. zip 안에서 바로 실행하면 켜지지 않습니다.
2. 윈도우는 `Framo.exe`, 맥은 `Framo 시작.command`를 더블클릭합니다. 윈도우 회사 백신이 서명 없는 `Framo.exe`를 막으면 같은 폴더의 `Framo 시작.bat`으로 켭니다(하는 일은 같습니다).
3. 크롬(없으면 엣지)이 탭과 주소창 없는 Framo 창(`http://127.0.0.1:41580`)으로 열립니다. 브라우저 프로필은 그대로라 예전에 만든 발표도 그대로 보입니다. 윈도우에서는 Framo를 켜 두는 검은 창이, 맥에서는 터미널 창이 같이 열립니다. 그 창을 닫으면 꺼집니다.

Framo는 서명을 받지 않은 오픈소스라서 처음 한 번은 운영체제가 막습니다. 윈도우가 "Windows의 PC 보호" 창을 띄우면 **추가 정보 → 실행**을 누릅니다. 맥은 "확인되지 않은 개발자" 안내가 뜨면 **완료**를 누른 뒤 **시스템 설정 → 개인정보 보호 및 보안**의 **그래도 열기**를 누르고 다시 엽니다. 127.0.0.1에만 묶기 때문에 방화벽 허용 창은 뜨지 않습니다.

나눠 줄 압축 파일은 `npm run pack`으로 만듭니다(`release/gyeol-windows.zip`, `release/gyeol-mac.zip`). 이때 개발 PC에서 nodejs.org의 공식 Node.js(윈도우 x64, 맥 arm64와 x64)를 한 번 받아 체크섬을 확인하고 넣습니다. `Framo.exe`는 Node.js의 단일 실행 파일(SEA) 기능으로 공식 `node.exe`에 작은 시작 코드(`launch/framo-exe.cjs`)를 넣은 것입니다(`scripts/exe.mjs`, postject). 아이콘(`launch/framo.ico`)과 파일 정보는 resedit(순수 JavaScript)가 넣어서 맥에서 묶어도 들어갑니다. 한글 파일 이름이 윈도우에서 깨지지 않게 zip을 직접 만들고, 윈도우용의 `.bat`은 CRLF, 안내 문서는 BOM을 붙인 UTF-8로 씁니다. zip 이름에 버전을 넣지 않아서 `releases/latest/download/gyeol-mac.zip` 같은 주소가 늘 최신 버전을 받습니다.

## 이렇게 씁니다

1. **새 발표 만들기**에서 발표 종류를 고릅니다. 열세 가지를 세 묶음으로 나눠 두었습니다.
   - **제안하고 결정받기:** 사업 제안, 개선 제안, 검토 보고(여러 안 비교), 고객 제안 계획, 연간·반기 계획
   - **진행과 결과 보고하기:** 주간·월간 업무 보고, 실적 보고, 결과 보고, 문제·장애 보고
   - **알리고 나누기:** 프로젝트 착수, 조사·분석 보고, 지식 공유·교육, 팀·업무 소개
2. 듣는 사람(본부장·임원, 팀장, 팀 동료, 다른 부서, 여러 분이 함께)과 시간을 고르면 몇 장으로 구성되는지 바로 보여 줍니다. 본부장·임원 앞이면 결론과 숫자 위주로, 팀 동료 앞이면 할 일과 진행 방법까지, 다른 부서 앞이면 배경부터 풀어 장을 고릅니다.
3. 제목, 소속, 발표자, **결정받고 싶은 것**(결정받을 것이 없는 발표는 부제)을 적고 테마를 고르면 편집 화면이 열립니다. 결정받고 싶은 것은 표지 오른쪽에 크게 들어갑니다.
4. 어느 발표든 표지 다음에 결론(**한 장 요약**)이 오고, 마지막은 받을 결정이나 부탁으로 끝납니다. 첫 두 장만 보고도 무엇에 관한 발표이고 무엇을 해 주면 되는지 알 수 있게 하는 순서입니다.
5. 슬라이드 위 글자를 눌러 바로 고칩니다. 누른 것 바로 위에 그것만의 도구가 뜹니다(항목 옮기기, 복제, 빼기, 모양 바꾸기). 표지와 섹션의 제목은 위에 뜬 '제목'을 잡고 위아래로 끌면 위, 가운데, 아래 자리에 붙습니다.
   - 오른쪽 **이 장 설정**에서 레이아웃과 모양, 바탕, 움직임을 고르고, 빈칸이 몇 곳 남았는지 보고 바로 갈 수 있습니다. 이 장에 무엇을 쓰면 되는지는 왼쪽 장 이름에 마우스를 올리면 보입니다.
   - 오른쪽 **컴포넌트**에서 큰 숫자, 전과 후, 차트, 일정, 비교 같은 컴포넌트를 장 위로 끌어다 놓아 장을 꾸밉니다. 컴포넌트 사이 경계를 끌면 너비와 높이가 칸에 맞춰 바뀌고, 컴포넌트 사이에 화살표 같은 이음표를 끼울 수 있습니다.
   - 고칠 때마다 저장됩니다. 바로 저장하고 싶으면 Ctrl+S(맥은 ⌘S)를 누르세요. 되돌리기는 Ctrl+Z, 다시 하기는 Ctrl+Y입니다.
6. **발표하기**(F5)로 전체 화면 발표를 하거나, **내보내기**로 파일을 만듭니다.
   - **발표 파일 (HTML):** 파일 하나로 열리고, 인터넷이 없어도 글꼴까지 그대로 보입니다. 미리 메일로 보내도 됩니다. 발표자 노트는 들어가지 않습니다.
   - **PDF:** 인쇄 창에서 "PDF로 저장"을 고르면 됩니다.
   - **PPT (그림):** PowerPoint 파일로 받습니다. 장마다 그림 한 장으로 들어가서 글은 고칠 수 없고, 발표자 노트는 PowerPoint의 노트 칸에 들어갑니다. 노트가 들어 있으니 다른 분께 보내기 전에 확인하세요.

처음이라면 홈의 **완성된 예시 보기**로 다 채운 보고가 어떻게 보이는지 먼저 확인해 보세요.

## 저장과 버전

처음 한 번 홈에서 **보관 폴더 고르기**를 눌러 PC 폴더(예: `문서/발표자료`)나 팀 공유 드라이브 폴더를 정해 두세요. 그 뒤로는 고칠 때마다 저장 버튼 없이 자동으로 저장됩니다.

```
발표자료/
├─ 한빛제조 품질 관리 제안.deck        ← 작업 파일 (발표자 노트 포함)
├─ 버전 기록/
│  └─ 한빛제조 품질 관리 제안/
│     ├─ 2026-10-23 15-12 본부장 보고본.deck
│     └─ 2026-10-23 16-40 자동.deck
└─ 지운 발표/                          ← 지운 발표는 여기로 옮겨 둡니다
```

- **두 곳에 저장:** 브라우저 안(IndexedDB)과 보관 폴더에 같이 저장합니다. 브라우저 기록을 지워도 폴더의 파일은 남고, 다른 PC에서 같은 폴더를 고르면 발표가 그대로 들어옵니다. 두 곳 내용이 다르면 더 최근에 고친 쪽을 열고, 덮이는 쪽은 버전으로 남깁니다.
- **버전 기록:** 편집 화면 위쪽의 시계 버튼을 누르면 열립니다.
  - **지금 상태를 버전으로 남기기**로 "본부장 보고본"처럼 이름을 붙이면 지우기 전까지 보관됩니다.
  - 자동 저장 버전은 열 때, 고치는 중 10분마다, 발표하거나 내보내기 전, 되돌리기 전에 남습니다. 발표마다 최근 30개(폴더에는 10개)를 둡니다.
  - 버전을 누르면 그때 모습을 장마다 보여 주고, 지금과 다른 장을 표시합니다. 되돌리면 되돌리기 전 상태도 버전으로 남으니 언제든 다시 돌아올 수 있습니다.
- **크롬, 엣지에서 씁니다.** 브라우저를 새로 열면 폴더 사용을 한 번 더 허용해야 합니다(홈과 편집 화면에 **허용하기**가 나옵니다).
- 작업 파일(.deck)과 발표 파일(.html)은 다릅니다. 작업 파일에는 발표자 노트가 들어 있으니 다른 분께 미리 보낼 때는 발표 파일을 쓰세요.

## 보안

- **이 PC 안에서만 돕니다.** 서버는 `127.0.0.1`에만 묶여 있어 같은 네트워크의 다른 PC에서 접속할 수 없고, 다른 주소 이름으로 들어온 요청은 거절합니다. 화면 파일만 내주고 발표 내용은 받지 않습니다.
- **발표 내용은 바깥으로 보내지 않습니다.** 화면과 내보낸 HTML 파일 모두 CSP로 바깥 주소 연결을 막습니다. 글꼴과 이미지도 모두 안에 들어 있습니다.
- **바깥 연결은 둘뿐입니다.** 직접 누르는 ‘AI에게 부탁’(이 PC의 Claude Code를 띄웁니다)과 새 버전 확인입니다. 새 버전 확인은 로컬 서버가 처음 화면을 열 때(하루에 한 번까지) GitHub의 이 저장소(`github.com/wlsdks/gyeol`)에 가장 최근 릴리스만 묻습니다. 함께 보내는 것은 Framo 버전뿐입니다. **받기**를 누르면 그 릴리스의 zip을 GitHub에서 받아, GitHub이 알려 준 SHA-256이 맞을 때만 Framo 폴더의 `새 버전`에 두고 폴더를 열어 줍니다. 풀거나 실행하지는 않습니다. 처음 화면의 버전 표시를 눌러 끌 수 있습니다. 다른 곳으로 가는 연결은 `scripts/offline.test.ts`(소스)와 `scripts/offline.mjs`(빌드 결과, `npm run pack`과 검수)가 막습니다.
- **저장은 두 곳뿐입니다.** 이 브라우저(IndexedDB)와 사용자가 고른 보관 폴더입니다.
- **AI는 모양만 다룹니다.** 아래 ‘AI에게 구성 맡기기’를 보세요.
- **오픈소스만 씁니다.** 모두 사내에서 써도 되는 라이선스(MIT, Apache-2.0, BSD, OFL 등)입니다. [docs/OPEN-SOURCE.md](docs/OPEN-SOURCE.md)에 정리했고, `npm run licenses`로 확인합니다.

## AI에게 구성 맡기기

Claude Code나 Codex가 발표의 **장 구성과 모양**을 보고 바꾸자고 제안할 수 있습니다. 적은 글은 AI에게 가지 않습니다. 장마다 있는 **AI로 다듬기**에서 “이 장을 더 보기 좋게”처럼 정해 둔 부탁을 고를 수도 있습니다(이 PC의 Claude Code를 도구 없이 띄워 모양만 보여 줍니다).

이 PC에 Claude Code가 있으면 위쪽 **AI** 버튼에서 부탁(보고 흐름 점검, 시간에 맞추기, 테마와 움직임, 장면 연출)을 고르기만 하면 됩니다. 처음 고를 때 이 발표의 모양을 AI에게 보여 줄지 한 번 묻습니다. Claude Code나 Codex에 직접 말로 부탁하려면:

1. 편집 화면 위쪽 **AI** 버튼을 누르고 아래 **보이는 것, 직접 연결**에서 **이 발표를 AI에게 보여 주기**를 켭니다. 발표마다 따로 켭니다.
2. 같은 곳의 **Claude Code, Codex에서 직접 쓰기**에 나오는 명령을 터미널에 한 번 입력합니다.
   ```bash
   claude mcp add gyeol -- node "<Framo 폴더>/dist-node/gyeol-mcp.mjs"
   codex mcp add gyeol -- node "<Framo 폴더>/dist-node/gyeol-mcp.mjs"
   ```
3. AI에게 “Framo(gyeol)에 공유한 발표를 본부장 보고에 맞게 구성을 다듬어 줘”처럼 말합니다.
4. 제안이 오면 편집 화면 오른쪽 아래에 알림이 뜹니다. 바뀌는 모습을 미리 보고 **적용하기**나 **거절하기**를 누릅니다.

- **AI에게 보이는 것:** 보고 종류와 시간, 장 순서와 레이아웃, 칸이 비었는지, 테마와 강조색. 편집 화면 위쪽 **AI 다듬기**의 **보이는 것, 직접 연결**에서 **보이는 내용 그대로 보기**로 직접 확인할 수 있습니다.
- **보이지 않는 것:** 제목과 적은 글, 숫자와 이미지, 발표자 노트, 소속·이름·연락처.
- **AI가 할 수 없는 것:** 칸에 글 쓰기, 내용이 있는 장이나 항목 지우기. 제안은 사람이 적용해야 바뀌고, 적용 전 상태는 버전으로 남습니다.
- AI와는 Framo 폴더 안의 `AI 공유` 폴더로만 주고받습니다. MCP 서버는 Node 권한 모델로 이 폴더 밖의 파일을 읽을 수 없게 실행됩니다.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173 (개발용. 저장소가 실제 주소와 따로입니다)
npm test           # 구성 생성 규칙, 작업 파일, 버전 비교, 로컬 서버, AI 공유, MCP 서버 테스트
npm run build      # dist/(화면)와 dist-node/(로컬 서버, MCP 서버) 만들기
npm start          # http://127.0.0.1:41580 으로 띄우기
npm run licenses   # 쓰는 패키지의 라이선스 확인
```
