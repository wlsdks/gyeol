# html-maker

팀장님, 본부장님께 하는 보고 자료를 PPT 대신 HTML로 만드는 도구입니다. 사업 제안, 고객 제안 계획, 개선 제안, 진행·실적 보고처럼 윗분께 무언가를 결정받는 자리를 위해 만들었습니다.

어떤 보고인지(종류, 보고 받는 분, 시간, 방식)를 고르면 그 보고에 맞는 장 구성과 레이아웃을 잡아 줍니다. 사람은 칸마다 적힌 안내를 보고 내용만 채우면 됩니다. 이 PC 안에서만 돌고, 내용은 어디로도 보내지 않습니다.

## 설치와 실행

받는 사람에게 필요한 것은 [Node.js](https://nodejs.org) (LTS) 하나입니다. `npm install`이나 인터넷 연결은 필요 없습니다.

1. 나눠 받은 `html-maker-<버전>.zip`을 풉니다.
2. 맥은 `html-maker 시작.command`, 윈도우는 `html-maker 시작.bat`을 더블클릭합니다.
3. 크롬(없으면 엣지)에 `http://127.0.0.1:41580`이 열립니다. 검은 창은 쓰는 동안 켜 둡니다.

나눠 줄 압축 파일은 `npm run pack`으로 만듭니다. `release/` 폴더에 생깁니다.

## 이렇게 씁니다

1. **새 발표 만들기**에서 보고 종류를 고릅니다.
   - **사업 제안:** 새 사업이나 프로젝트를 하자고 제안하고 승인받습니다.
   - **고객 제안 계획:** 어느 고객에게 무엇을 얼마에 제안할지 보고하고 승인받습니다.
   - **개선 제안:** 일하는 방식, 제도, 도구를 바꾸자고 제안합니다.
   - **진행·실적 보고:** 맡은 일의 실적과 진행 상황을 보고하고 지원을 요청합니다.
2. 보고 받는 분(본부장·임원, 팀장, 여러 분이 함께)과 시간을 고르면 몇 장으로 구성되는지 바로 보여 줍니다. 본부장·임원 보고는 결론과 숫자 위주로 장 수를 줄입니다.
3. 제목, 소속, 발표자, **결정받고 싶은 것**을 적고 테마를 고르면 편집 화면이 열립니다. 결정받고 싶은 것은 표지 오른쪽에 크게 들어갑니다.
4. 어느 보고든 표지 다음에 **한 장 요약**(결론과 요점)이 오고, 마지막은 **결정 요청**으로 끝납니다. 윗분이 첫 두 장만 보고도 판단할 수 있게 하는 순서입니다.
5. 슬라이드 위 글자를 눌러 바로 고칩니다. 오른쪽에는 이 장에서 무엇을 말해야 하는지, 아직 비어 있는 칸이 어디인지 나옵니다.
6. **발표하기**(F5)로 전체 화면 발표를 하거나, **내보내기**로 파일을 만듭니다.
   - **발표 파일 (HTML):** 파일 하나로 열리고, 인터넷이 없어도 글꼴까지 그대로 보입니다. 미리 메일로 보내도 됩니다. 발표자 노트는 들어가지 않습니다.
   - **PDF:** 인쇄 창에서 "PDF로 저장"을 고르면 됩니다.

처음이라면 홈의 **완성된 예시 보기**로 다 채운 보고가 어떻게 보이는지 먼저 확인해 보세요.

## 저장과 버전

처음 한 번 홈에서 **보관 폴더 고르기**를 눌러 PC 폴더(예: `문서/발표자료`)나 팀 공유 드라이브 폴더를 정해 두세요. 그 뒤로는 고칠 때마다 저장 버튼 없이 자동으로 저장됩니다.

```
발표자료/
├─ 한빛제조 품질 관리 제안.deck        ← 작업 파일 (발표자 노트 포함)
├─ 버전 기록/
│  └─ 한빛제조 품질 관리 제안/
│     ├─ 2026-10-23 15-12 본부장 보고본.deck
│     └─ 2026-10-23 16-40 자동.deck
└─ 지운 발표/                          ← 지운 발표는 여기로 옮겨 둡니다
```

- **두 곳에 저장:** 브라우저 안(IndexedDB)과 보관 폴더에 같이 저장합니다. 브라우저 기록을 지워도 폴더의 파일은 남고, 다른 PC에서 같은 폴더를 고르면 발표가 그대로 들어옵니다. 두 곳 내용이 다르면 더 최근에 고친 쪽을 열고, 덮이는 쪽은 버전으로 남깁니다.
- **버전 기록:** 편집 화면 위쪽의 시계 버튼을 누르면 열립니다.
  - **지금 상태를 버전으로 남기기**로 "본부장 보고본"처럼 이름을 붙이면 지우기 전까지 보관됩니다.
  - 자동 저장 버전은 열 때, 고치는 중 10분마다, 발표하거나 내보내기 전, 되돌리기 전에 남습니다. 발표마다 최근 30개(폴더에는 10개)를 둡니다.
  - 버전을 누르면 그때 모습을 장마다 보여 주고, 지금과 다른 장을 표시합니다. 되돌리면 되돌리기 전 상태도 버전으로 남으니 언제든 다시 돌아올 수 있습니다.
- **크롬, 엣지에서 씁니다.** 브라우저를 새로 열면 폴더 사용을 한 번 더 허용해야 합니다(홈과 편집 화면에 **허용하기**가 나옵니다).
- 작업 파일(.deck)과 발표 파일(.html)은 다릅니다. 작업 파일에는 발표자 노트가 들어 있으니 다른 분께 미리 보낼 때는 발표 파일을 쓰세요.

## 보안

- **이 PC 안에서만 돕니다.** 서버는 `127.0.0.1`에만 묶여 있어 같은 네트워크의 다른 PC에서 접속할 수 없고, 다른 주소 이름으로 들어온 요청은 거절합니다. 화면 파일만 내주고 발표 내용은 받지 않습니다.
- **바깥으로 연결하지 않습니다.** 화면과 내보낸 HTML 파일 모두 CSP로 바깥 주소 연결을 막습니다. 글꼴과 이미지도 모두 안에 들어 있습니다. `npm run pack`은 빌드 결과에 바깥 주소가 섞이면 멈춥니다.
- **저장은 두 곳뿐입니다.** 이 브라우저(IndexedDB)와 사용자가 고른 보관 폴더입니다.
- **AI는 모양만 다룹니다.** (만드는 중) Claude Code나 Codex를 MCP로 연결해도 AI는 장 구성과 레이아웃만 보고 고칠 수 있게 하고, 적어 넣은 글은 넘기지 않습니다. 자세한 설계는 [docs/DESIGN.md](docs/DESIGN.md)에 있습니다.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173 (개발용. 저장소가 실제 주소와 따로입니다)
npm test           # 구성 생성 규칙, 작업 파일, 버전 비교, 로컬 서버 테스트
npm run build      # dist/ 에 화면 파일 생성
npm start          # dist/ 를 http://127.0.0.1:41580 으로 띄우기
npm run pack       # 나눠 줄 폴더와 zip 만들기
```

설계와 앞으로 할 일은 [docs/DESIGN.md](docs/DESIGN.md)에 있습니다.
